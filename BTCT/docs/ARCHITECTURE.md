# Architecture and detail reference

This file is the detailed reference for BTCT: architecture, every invariant with its full text, and the command detail. The always-loaded `CLAUDE.md` at the repo root keeps only the short form of each and links here.

BTCT ("Been There, Conquered That") is a real-time, multi-user pentest note-taking app: collaborative markdown pages, nmap import, team command capture and shared screenshot assets with non-destructive crop and redaction. Runtime is **Bun** everywhere; the whole thing ships as one Docker image. It is built to run on a small box (1 to 2 GB of RAM, 1 to 2 cores), so a feature that costs steady memory or CPU has to earn it.

## Writing style for generated prose

**Never use em dashes (`—`) in anything you write.** Not in docs, not in commit messages, not in code comments, not in PR descriptions, not in the blog. An em dash is almost always a decision that got skipped, so make the decision instead:

| Instead of | Use |
|---|---|
| `Notes went in Word — five operators, five documents` | a full stop: `Notes went in Word. Five operators, five documents` |
| `- **Term** — definition` | a colon: `- **Term**: definition` |
| `read — and, when allowed, edit — the workspace` | parentheses: `read (and, when allowed, edit) the workspace` |
| `it renders offline — no network calls` | a comma: `it renders offline, with no network calls` |
| a table cell containing only `—` | `none` |

En dashes are fine in real ranges (`H1–H3`, `3–32`) and inside literal UI strings you are quoting. Run `grep -c '—' <file>` before you call a doc change done. It should be `0` everywhere; the table just above is the only deliberate exception in this repo, because it has to quote the character to name it.

Related habits worth keeping: skip the ban-list words (seamless, leverage, robust, comprehensive, delve, unlock, supercharge), do not bold every feature noun, and vary sentence length instead of writing everything at 20 words.

## Commands

Client (repo root; run scripts with `bun run`):
- `bun install`: install client deps.
- `bun run dev`: Vite dev server (hot reload). Needs the server running separately (below).
- `bun run build`: **typecheck + build**: `tsc -b && vite build`. This is the canonical "does it compile" check.
- `bun run test`: Vitest (all suites, in `src/test/`).
  - Single file: `bun run test -- src/test/pane-layout.test.ts`
  - Property tests (`fast-check`) live in `src/test/properties-*.test.ts`.
  - By name: `bun run test -- -t "moveTab"`
- `bun scripts/codemod-tokens.mjs [--check] [paths]`: rewrites `bg-[hsl(var(--x))]`-style classes and `text-[Npx]` sizes to the token utilities (`--check` only reports, exit 1 when something would change).
- `bun run fonts`: stage the 17 default Typst report fonts (`scripts/fonts.ts`, CDN fetch with a skip-if-present check, written to a `.partial` name and renamed so an interrupted fetch leaves nothing to trust) into `public/fonts/`, which is gitignored **and dockerignored**, so the image build always fetches them rather than copying a local copy. The Dockerfile runs this before `bun run build` and then asserts `dist/fonts` holds 17 files, since a missing font only shows up at runtime as a font load error (the static handler answers a missing file with a 404). A `WITH_TYPST_CLIENT=0` image build skips the fetch and deletes `dist/fonts` and the typst wasm instead.

Server (in `server/`, plain `.mjs`, no build step; Bun runs it directly):
- `cd server && bun install`
- `cd server && bun run dev`: server with `--watch`. Requires env: `AUTH_SECRET`, and set `YPERSISTENCE=./data/yjs` or Yjs rooms are memory-only (the Docker image sets `YPERSISTENCE=/data/yjs` itself; an empty value counts as unset, see `server/env.mjs`, which `index.mjs` imports first). For a full local dev pair, run this + `bun run dev` in two terminals (client falls back to same-origin; set `VITE_API_URL`/`VITE_WS_URL` only for a split host).

## Architecture: the big picture

### There is no traditional database. Data lives in Yjs CRDT documents.

The "DB" is a set of **Yjs documents** synced over WebSockets and cached in IndexedDB. Every data change flows:

```
UI → repo/store action → write a Y.Map / Y.Text (inside doc.transact)
   → y-websocket broadcasts to server + peers → each client's Y observer fires
   → shared-bindings re-derives Zustand state (debounced) → React re-renders
```

`src/db/database.ts` looks like Dexie (`get/add/put/update/where().equals()`) but is a shim over the shared Y.Maps, **not** a local database. A write there propagates to *every connected user*.

### Two-tier Yjs design

| | Shared doc (`src/realtime/shared-doc.ts`) | Per-page doc (`src/realtime/yjs-providers.ts`) |
|---|---|---|
| Room | `btct-shared` | the page's `id` |
| Holds | all entity records (one `Y.Map` per table) + one `texts` `Y.Map` of `Y.Text`s | one page body as a `prosemirror` `Y.XmlFragment` |
| Edited by | repos/stores | Milkdown collab plugin |

- **Records** = plain JSON in a per-table `Y.Map` keyed by `id` (last-writer-wins). Tables: `workspaces, pages, changeLogs, pageSnapshots, nmapScans, nmapMachines, typstAssets, assetFolders, commandLogs`. One more map, `settingsPublic`, is a **server-written** mirror of the public settings (the admin theme policy under key `theme`, stamped `themeUpdatedAt`, and the blur-strength defaults under key `blur`, stamped `blurUpdatedAt`); clients only read it.
- **Collaborative text fields** (page title/slug, workspace name, nmap-scan name, nmap hostname) are authoritative as a `Y.Text` in the `texts` map, keyed `<entity>:<id>:<field>`. A `mirrorTextsToRecords` observer copies each `Y.Text` back into the JSON record so everything else reads plain JSON. The Typst report source is the one `Y.Text` with no JSON record behind it: key `typst:<workspaceId>:source`, one per workspace, seeded by `useTypstSource` (`components/typst/use-typst-source.ts`) with `getOrInitYText` once `whenReady` has resolved, and edited by CodeMirror through `yCollab`, so it is not in `TEXT_FIELDS_BY_ENTITY` and the mirror ignores it. Rewrites from code go through `replaceYTextContent` like any other (invariant #3b): the ZIP import, plus `TypstView` itself for slot placement and height, rename retargeting, add slot, search replace-all and Import report. Those six all run through `applySource`, which takes a function of the CURRENT text and calls `updateYTextContent`, because the view renders a 120 ms trailing mirror of the `Y.Text` and a rewrite computed from that mirror deletes whatever a collaborator typed inside the window.
- **Page icons are ASCII only**: `scrubEmojiIcons` (`shared-doc.ts`) clears any non-ASCII `icon` on every doc load (with `seedMissingYTexts`, after the IndexedDB load and on the provider's first real `sync` against the captured ctx, never on `whenReady`; invariant 1), in every workspace, imported and restored pages included. A deliberate product decision; do not "fix" it without one.
- **Page bodies never go in the shared doc**: they're per-page docs. Their version history lives on the server (`server/history.mjs`, see below); the old `pageSnapshots` map is read once for import and no longer written.

### Client layers
- `src/db/*-repo.ts`: one repo per entity: CRUD + queries, pre-seeds `Y.Text`s on create, cascades deletes.

Its `renameFindingArg(src, from, to)`, `addFindingArg(src, name, literal)` and `removeFindingArg(src, name)` rewrite every `#finding` block of a report in one minimal-delta pass (blocks edited last to first). The schema and `typst-findings.ts` import each other, so neither may touch the other at module top level. **Copy / Paste finding** (`lib/typst-finding-copy.ts`, pure): the clipboard payload is the plain block (marker, call, its `#end-of-block`) dedented under one `// @btct-finding-copy v=1 workspace=<id>` comment, written with `copyText` (works over http) and read back from a real paste event (the rail's own `onPaste`, or the Paste window's textarea; never `navigator.clipboard.read`). `pasteFindings` gives every block an id free in the report (`freshFindingId`), keeps its status, fits `#end-of-block` to the target, adds the helpers Add would and follows the No severity rule (`allowNoSeverity`, else refused); it is a dry run first, against the settled source, so a refused paste copies nothing. For a paste from another workspace, `planAssetCopies` looks each `/assets/<file>` up by name in the source workspace's records (`typstAssetRepo.getByWorkspace`); a file this workspace lacks is fetched and uploaded again through `addTypstAsset` (its name made unique) with the crop and blurs set by `setTypstAssetCrop`, and `rewriteAssetPaths` points the block at the new name; an identical image already here (bytes and framing, whatever its name) is reused; what is nowhere is pasted anyway and listed in the notice. Same-workspace paste is a duplicate with no asset copies. Tests: `src/test/typst-findings.test.ts`, `typst-finding-schema.test.ts`, `typst-finding-copy.test.ts`, `typst-exploit-steps.test.ts`, `asset-link.test.ts`.

### Note images are shared assets (`src/lib/asset-image.ts` + `note-image-paste.ts`)
Pasting/dropping an image into a note does NOT embed bytes: `noteImagePastePlugin` (capture-phase `paste`/`drop` listeners on the editor DOM, because Milkdown's clipboard plugin owns the `handlePaste` prop and would consume the event first) uploads it via `addTypstAsset` and inserts an `asset_image` node that references the asset by id. So a note image appears in the Assets Manager and shares its non-destructive crop/blur pipeline. The `asset_image` node is a custom `$node` + plain-DOM `$view` (never Crepe's Vue image view): the view renders `resolveAssetBytes(asset)` (crop + blur applied) as a blob URL and subscribes to the store so a blur committed in the editor updates the note live; `data-asset-id` is mirrored onto the DOM for the right-click menu. Editing opens `ImageEditorDialog` via the `editingAssetId` store flag and the app-level `AssetImageEditor` host; the right-click menu and the `blurImage` keybind (`Mod-Shift-b`) both open it. The menu's **Copy image with blur** copies `resolveAssetBytes(asset)` (the note's own render, crop and blur baked, never the original) as PNG through `copyImage` (`lib/clipboard.ts`): `navigator.clipboard.write` in a secure context, else a `copy` event carrying it as an HTML `data:` image, which a note paste turns back into an upload (`dataImageFileFrom`, a lone `<img>` only). The original upload is never overwritten, so a blur is always removable. Markdown round-trips as `![](asset:<id>)`. **Copy link** on an Assets card (hover button or right-click menu, `AssetsPanel`) copies `btct-asset:<id>` through `lib/clipboard.ts` (`navigator.clipboard` in a secure context, else a hidden-textarea `execCommand('copy')` in the same click task, else the text shown for a manual copy); pasting one into a note inserts the `asset_image`, into the report code a filled slot (`assetLinkPaste` in `TypstEditor.tsx`). The link is resolved where it is pasted and never stored (invariant 35). `renameTypstAsset` itself repoints `/assets/<old>` literals in the workspace report `Y.Text` (`updateYTextContent` + `retargetAssetPath` from `src/lib/asset-retarget.ts`, a Typst-free helper), so callers must not retarget separately. `asset_image` is in image-resize's `IMAGE_TYPES`, so the drag-resize handle works on it too. The read-only history viewer (`HistoryView`) includes `asset_image` in its schema (`crepe.editor.use(assetImageSchema)`) and gives it a `nodeViews` entry that resolves the bytes, so a version you're about to restore shows the actual picture (a placeholder once retention has pruned it). `noteImageCleanupPlugin` retires the asset 10 s after its last `asset_image` leaves the doc, only if no other note in the workspace (`asset:<id>` in page content) and not the report source (`/assets/<filename>`) still references it; the check runs when the timer fires (only on the removing client; a re-insert cancels it) and un-retires a retired asset whose image is inserted again; it walks the doc only when a step touched an image. Uploads land through mapped placeholder decorations; a failed upload keeps the File and offers Retry through `EditorNotices` (`src/lib/editor-notices.ts`), and a text paste over 1,000,000 characters is refused with a Save as .txt offer (the relay's 16 MiB message limit would drop it). Rendered image bytes sit in a 64 MB `ByteLru`, Assets cards load near the viewport and show a 320 px thumbnail (`resolveAssetThumbnail`). A `shortcuts` TabKind renders `src/components/help/ShortcutsView.tsx`, a grouped cheat-sheet whose editor rows read the account's live keybinds; its last card lists the `btct` subcommands (`BTCT_CLI_ROWS`, rows flagged `mono` render as wrapping monospace code instead of a key chip).

Cropping and sizing are two separate things. The crop is the asset's `CropRect` (shared by every use of the image): `FigureViewport` pans and zooms the image behind a fixed frame, and with `onCropResize` its edge handles pull a side of the frame in; on release `cropFromSelection` (`lib/crop-math.ts`) turns what is left into the new crop and the dialog gives the frame that shape (`ImageEditorDialog` sets its own aspect; `PlaceScreenshotDialog` keeps the figure's width and changes its height). The size belongs to each use: a note image's `width` attr (corner drag, or the right-click **Size** row through `setImageWidthFraction`), and a Typst figure slot's `width:` ratio of the text width with its `height:` scaled to match. A slot only takes `width:` once the report's `image-placeholder` declares it: `ensureHelperWidth` (`lib/typst-placeholders.ts`) swaps in the current built-in helper, or for a customized one (the BTCT report template's) adds `width: <first width literal in its body>` to the parameters and points those literals at it, leaving the styling alone. `ImageBlock.width` carries the same argument through the finding step editor, whose **Add template screenshot** writes the empty slot the report's `template-exploitation` uses.

### Command log ingest (`server/cmdlog.mjs` + `cmdlog-agent/`)
A standalone Python 3 agent (`cmdlog-agent/`, stdlib-only) runs on each operator's Kali box: a bash/zsh shell hook captures whitelisted commands to a per-PID spool file, and a daemon correlates start/exit, redacts secrets, and batch-POSTs them to `POST /api/cmdlog/events` (static bearer ingest token). Storage is **split on purpose**:
- **SQLite `command_logs`** (`db.mjs`) is the durable, unbounded archive; rows are **upserted by the agent-generated `id`** so a start event and its later exit/duration completion merge, and a replayed batch is idempotent. Read with filters over `GET /api/cmdlog/query`; `GET /api/cmdlog/export` streams the whole archive (json, csv or count) in keyset pages of 500 rows, never one cursor held across an await, and `POST /api/cmdlog/import` upserts up to 1000 rows a request (an id owned by another workspace becomes `imp-<sha256(ws,id)>`; a ZIP body, told by its `Content-Type` or its first bytes, gets 415).
- **The shared doc's `commandLogs` map** (written via `appendCommandLogs` in `yjs-data.mjs`) is a **bounded live window** (~500/workspace, pruned oldest-first) so the Command Log tab updates live without polling. It has **no Y.Text fields**, all LWW JSON (like `typstAssets`), so invariant #1 doesn't apply.
- The client view (`src/components/cmdlog/CommandLogView.tsx`, a `cmdlog` TabKind) **seeds from REST on mount, then follows the CRDT**, sidestepping the cold-doc problem where server CRDT writes are lost if `YPERSISTENCE` is unset and no browser is connected. Pure filter/CSV logic is in `src/lib/cmdlog-filter.ts` (tested). The agent sends at most 200 events a POST (the server's cap; `--batch-size` is clamped) and re-sends events past the reply's `accepted` + `skipped`, cuts commands to 4096 characters, splits a refused batch and drops (counts as `rejected`) an event the server still refuses alone, retries 401/403/404/405/408/409/429, 5xx and network errors, and keeps its outbox as an append-only JSONL with a committed offset.

### Retired features (`src/export/retired.ts`)
Web recon, the attack-narrative graph canvas, findings, the attack timeline, attack chains and the in-app Claude assistant were removed. Their UI, routes, repos, store slices, subscriptions and `TABLE_NAMES` entries are gone, so a running client pays nothing for them. (The Typst report tab was removed in the same pass but came back on 2026-09-19 behind `ENABLE_TYPST`; it never had a table in this file's `TABLES` list, since its source is a `Y.Text`, not records.)

What is **not** gone is the data. The old Y.Maps (`siteMaps`, `siteMapNodes`, `siteMapEdges`, `graphs`, `graphNodes`, `graphEdges`, `attackChains`, `timelineEvents`) still exist inside the shared doc of any workspace that had them, and `src/export/retired.ts` reads and writes them directly off `getSharedDoc()`, so:
- a workspace ZIP exported by this build still carries every one of those records, under `.btct/` with the same filenames older builds wrote, and
- importing such a ZIP puts them back, with ids remapped exactly like live records.

Adding a table to `TABLES` in that file is all it takes to retire another feature the same way. Full server backups copy the whole doc, so they preserve these records regardless. There is deliberately **no prune**: dropping the maps would destroy the only copy of an old engagement's graph.

### Workspace archive (`src/export/`)
Schema 3: a `<workspace>_<YYYY-MM-DD_HHMM>/` folder with a human `notes/` tree (a folder per page, `<Title>.attachments/NN-<stem>/modified|original.<ext>`, `Command log.csv`), `assets/` and a lossless `.btct/` (every table uncapped, asset records, folders, `commandLogs.json`, `pageYjsUpdates.json`, `report.typ`, retired tables). `workspace-zip.ts` is a pure plan, a writer and a parser (schema 2 and 1 still parse); `export-workspace.ts` gathers, `import-workspace.ts` writes. Several workspaces export into one ZIP as sibling schema-3 roots (`exportWorkspacesArchive` gathers and adds one workspace at a time through `addWorkspaceToZip`, which suffixes a root that already exists ignoring case; `btct-workspaces_<stamp>.zip` for two or more, the plain single-workspace name for one), and `parseWorkspaceZips` returns one parsed archive per `<root>/.btct/manifest.json`, each reading only inside its own root, falling back to the single-archive parser (top-level `.btct/`, schema 2, schema 1) when there is at most one root. The dialog imports them in turn and keeps going past a failed one. Bodies are read through read-only providers (`page-bodies.ts`, `?ro=1`, no IndexedDB, no BroadcastChannel; the server skips `trackPageDoc` for them), and an imported body counts only when a second read-only connection sees the server's state vector cover it. Import as new remaps every id (including the page records inside a delete entry's `pageTree` snapshot) and asks the server for new asset ids; replace keeps ids, overwrites in place, deletes only ids the archive lacks and merges bodies. Names come from `src/lib/export-names.ts`, downloads from `src/lib/download.ts` (wrapped in a ZIP by `download-zip.ts` for everything but the workspace and notes archives and the Report tab's report bundle). Not in the archive: version history, accounts, settings, unselected workspaces (that is what a backup is for).

### Data retention (`server/retention.mjs`)
Admin-configurable, OFF by default (`settings.retention_days = 0` = keep forever). When set to N days, a `createJob` (scheduler.mjs) run on boot + every 6h deletes `page_versions` older than N days and permanently removes assets that were RETIRED (soft-deleted) more than N days ago (bytes under `ASSETS_DIR`, the `assets` SQLite row, and the shared-doc `typstAssets` record, read via `doc.getMap('typstAssets')` since the server's `TABLE_NAMES` omits it). Last run is persisted in `settings.retention_last_run`, so an overdue prune fires right after boot (same pattern as backups). Note-image deletion RETIRES the asset (`deletedAt` on the record, hidden from the Assets Manager) rather than hard-deleting, so history keeps showing the image until the window prunes it; the Assets Manager's own delete button still hard-deletes. Admin routes `/api/retention/*` (config, run, history-range) are admin-only. `startRetentionScheduler()` is called at boot in `index.mjs`.

### Backups (`server/backup.mjs`, `data-export.mjs`, `restore.mjs`, `scheduler.mjs`, `backup-format.mjs`)
The server snapshots itself into `BACKUP_DIR`, one **self-contained ZIP per run** (`btct-backup-YYYYMMDD-HHMMSS.zip` holding `yjs/<room>.yupdate.gz`, `sqlite/data.sqlite.gz`, `assets/<id>`, `history/<pageId>.ydoc` and `manifest.json` last), streamed by `server/zip-stream.mjs` (STORE + CRC32, local headers patched after each entry, ZIP64 only when needed, bounded memory: 192 MB in 7.4 s at +50 to 70 MB RSS) into `<name>.zip.tmp`, fsynced, chmod 0600 and renamed. Folder runs from older builds (`btct-backup-<stamp>/`, hard-linked assets) are still listed, verified, restored and counted for keep-last; nothing writes them any more. Reads go through `data-export.mjs` only: SQLite via `VACUUM INTO`, each Yjs room as one update (from the relay's in-memory doc when open, else y-leveldb), assets copied by id. **Never copy the live SQLite file or LevelDB directory** (invariant #12). `scheduler.mjs` is a single-timeout job (no overlap, persisted last run so an overdue backup fires right after boot); config lives in `settings` (`backup_*` keys) and the admin UI saves it per change. Status, run-now and the ZIP download (`GET /api/backup/archives/<name>`) also accept a static `backup_token` (same static-bearer pattern as the command-log ingest token) for host schedulers; the admin panel saves a run to the operator's computer through the system save dialog or a one-time-ticket link (invariant 32). Order: drain the relay persistence, rooms (a room that fails or times out goes to `manifest.failedDocs`), SQLite snapshot, assets listed in the snapshot, twins; a run has a deadline, a per-room timeout and a statfs precheck. Every ZIP is a full copy, so the statfs precheck counts every asset plus the raw SQLite scratch file, and keep-last (`backup_keep_last`) defaults to `KEEP_LAST_DEFAULT` (12) when unset, an explicit 0 keeping all; stale `.zip.tmp` files and `.tmp` folders are removed at boot; run summaries are cached for status/list; `backup_last_good` is kept apart from the last result; a run complete on disk stays a success (and is pruned) even when SQLite cannot record its result; a failed scheduled run retries after min(interval, 5 min). `restore.mjs` is a CLI for a stopped server that takes a ZIP or a folder: verifies hashes and manifest ids (a ZIP in place, member names refused when they could leave a folder, CRC32 checked) and decodes every payload (`restore-checks.mjs`; a ZIP's members are read from the archive, not unpacked), refuses while another process holds a lock on LevelDB's `LOCK`, the SQLite file or its `-shm` (asked with `fcntl(F_GETLK)` through `bun:ffi`, which writes nothing; opening the stores is only the logged fallback), so a refused run leaves `/data` byte-identical, unpacks a ZIP's needed members into `.restore-unpack` (re-hashed, removed on exit), stages into `.restore-staging`, reads every room back, then swaps with the old data in `pre-restore-<stamp>/`; keeps the box's `backup_*` settings (a box with no settings yet takes the backup's config, token and instance id but none of its run history, `BACKUP_RUN_HISTORY_KEYS`) and writes `restore_epoch` (`src/realtime/restore-epoch.ts` clears browser caches on a new one). `backup-format.mjs`, `zip-stream.mjs` and `scheduler.mjs` are unit-tested from `src/test/` through `.d.mts` declarations.

### Page version history (`server/history.mjs`, `server/history-diff.mjs`, `src/components/history/`)
Google Docs-style, and the reason the server keeps a second copy of every page. Live page docs are GC-on, so deleted text vanishes once every client has seen the deletion; `trackPageDoc` (called from the websocket `connection` handler for every room but `btct-shared`) keeps a **GC-off twin** fed by the relay doc's `update` events and flushed atomically to `HISTORY_DIR/<pageId>.ydoc` (temp file, fsync, rename, off the event loop, only when it changed; a twin that cannot be parsed is renamed to `<pageId>.ydoc.corrupt-<ts>` and counted in `historyStatus()`, never overwritten). A **version** is `Y.snapshot(twin)` in the `page_versions` SQLite table (`trigger` auto/named/restore/import, name, creator, `changed_by`); imports from the legacy `pageSnapshots` map carry full `state` instead. Policy: auto 2 minutes after the last update, every 10 minutes of continuous editing, and on room close, skipped when the body did not change; nothing is thinned. Attribution: clients call `attachUserMapping` (`Y.PermanentUserData`, `users` map, description = account id) after sync; `changedUsersBetween` (pure, `Y` injected, tested in `src/test/page-history.test.ts`) counts only items inside the `prosemirror` fragment. Client: `page-history-api.ts` (routes, twin download), `HistoryView.tsx` (TabKind `history`; own read-only ProseMirror with the editor's schema plus `ychange` from `lib/history-schema.ts`, built once from a headless Crepe that must stay alive because node `toDOM`s read its ctx; y-prosemirror's snapshot renderer does the per-user colouring), `page-snapshots.ts` (`restoreFromState`: one ProseMirror transaction through the registered page editor, `lib/active-editor.ts`, else a fragment clone; `restorePageVersion` waits for the provider's own sync first, and the editor registers for restores only once collab-bound), `PageHistoryPanel.tsx` (launcher + named save). Backups copy the twins as the `history` category.

### Server (`server/`): intentionally thin
Bun `node:http` + `ws`. It does **auth + static hosting + a Yjs relay** and knows almost nothing about what a page or a scan means. `bun:sqlite` (`db.mjs`) stores only `users`, `settings`, `page_versions`, `command_logs`, `assets` (blob inventory: size/mime, never meaning). Routing is a flat `if (method && url)` chain in `index.mjs` using `authFromHeader`/`requireAdmin`/`readJsonBody`/`sendJson`. Auth = PBKDF2 passwords + HMAC-signed tokens (`auth.mjs`), 7-day TTL; the websocket upgrade and the backup routes also check that the account still exists, and deleting an account terminates its open relay sockets (`closeUserSockets`). Each relay socket's messages pass through `server/relay-inbox.mjs` (queued, then applied 256 per event-loop turn in one transaction; a socket past 20,000 waiting messages or 64 MiB is cut off and its client resends on reconnect). Relay persistence is `server/relay-persistence.mjs` (one write per room every 300 ms, grouped merges up to 1000 buffered updates and a state-vector diff past that, kept failures, compaction every 15 min, `drain()`, `status()`); `/healthz` answers 503 while it fails (after a failed write, until the LevelDB log is sealed) or while shutting down, and `GET /api/admin/status` reports it with disk and twin health. SIGTERM/SIGINT run `shutdown()`: close rooms, drain and close LevelDB, close SQLite, exit 0 (forced exit after `SHUTDOWN_TIMEOUT_MS`). A missing static file is a 404; only extensionless paths fall back to `index.html`.

## Critical invariants

Read these before touching the data layer. They are non-obvious and easy to break; full list in README "Conventions & invariants". The root `CLAUDE.md` carries each one as a single line.

1. **Pre-seed `Y.Text`s in every repo `create()`** (`getOrInitYText(textKey(...))`) or two clients race and orphan the text. A *new* collaborative field means touching all four: `TEXT_FIELDS_BY_ENTITY` + `TEXT_FIELD_TO_TABLE` (`shared-doc.ts`), the repo `create()`, and the UI (`useYTextInput`). The report source is the one field no repo creates, so the tab seeds it on open (`useTypstSource`), and only once something proves nothing is coming: the key is already in the local doc (adopt it, offline or not) or **the websocket provider reports `synced`**. `whenReady` gates the first of those but cannot authorize a seed, since it also resolves on its own 4 s cap. Seeding a cold client writes a second `Y.Text` into the slot concurrently with the real one arriving, and Yjs picks the winner by client id, so half the time the starter template replaces a report that has no version history. An offline client with no cached report waits (the tab says "Waiting for the workspace to sync…" after 4 s) rather than seeding.
2. **Read the JSON record, not the `Y.Text`.** The mirror keeps them in sync; only the editor/input layer touches `texts`.
3. **Never rebuild the editor to apply settings.** Keybinds and code accent flow through module-level refs + CSS vars specifically so the Yjs collab binding survives; remounting drops live cursors/edits.
3b. **Programmatic Y.Text rewrites use `replaceYTextContent`** (minimal delta). A clear-and-reinsert destroys remote cursors and can't merge with a concurrent edit.
3c. **A drag writes to the DOM, once per animation frame, and commits to React state only on pointer-up.** Pane resizing does it for the reason in #3 (a mid-drag re-render can remount an editor and drop its collab binding); the crop window's blur, pan and crop-handle gestures do it for cost: a pointer fires up to 1000 events a second against a 60 Hz display, and a `setState` per sample measured 3.2 ms of render work per event with a dozen blur regions on screen. Never put a `backdrop-filter` on an element a drag resizes either, or the compositor re-blurs the whole backdrop per sample. Width math + persistence live in `src/lib/pane-resize.ts` (pure, tested); `src/test/viewport-drag.test.tsx` guards the crop window by counting commits, not milliseconds.
4. **Keep the server dumb about domain data.** Five deliberate exceptions: `backup.mjs` + `data-export.mjs` (move bytes: a `VACUUM INTO` snapshot, per-room Yjs updates, asset copies; they know room names, never meaning), `history.mjs` (keeps a per-page twin doc and its versions), `assets.mjs` (stores opaque blobs; knows size + mime, never meaning), `cmdlog.mjs` (ingests externally-produced command records into SQLite + the CRDT; validates and stores, knows nothing about what a command means), and `server/typst/` (stages a report and its images for export; reads the report source and the asset records through `yjs-data.mjs`, writes nothing to the shared doc). `yjs-data.mjs` is the only module that reaches into the shared doc, and it is now down to what those need: `listWorkspaces`, `appendCommandLogs`, the two `settingsPublic` mirrors, the asset-retention pair, and `readTypstSource` + `listAssetRecords`. Nothing there writes a `Y.Text`; if you add something that does, it must set BOTH the `Y.Text` and the JSON record.
4b. **Never put binary content in the shared doc.** Upload it and reference it by id (see the note-images section). Page versions are server-side too (`page_versions` + `HISTORY_DIR`); the legacy `pageSnapshots` map is import-only.
4c. **Live page docs are GC-on, the history twins are GC-off, and twin files never pass through y-leveldb.** `server/history.mjs` feeds each twin from the relay doc's `update` events and writes it atomically to `HISTORY_DIR/<pageId>.ydoc`; a version is a `Y.snapshot` of that twin, so deleting the twin file makes every diffable version of that page unrenderable (imports keep their own full state). Attribution only works while clients call `attachUserMapping` after sync and only counts items inside the `prosemirror` fragment (`server/history-diff.mjs`). Restores go through the live editor when the page is open (`restoreFromState`), never a clear-and-reinsert on a doc someone is typing in.
5. **DB migrations must be idempotent.** Guard every `ALTER TABLE` with a `PRAGMA table_info` column check (see `db.mjs`).
6. **Load `yjs` on the server via the same CJS require as y-websocket** (`require('yjs')`, not `import`), or you get two Yjs instances and `Y.Text` writes silently fail to integrate.
7. Deletes cascade in one transaction and are logged with a snapshot of every removed record (a page's subtree as `{kind:'pageTree', pages}`, bodies up to 256 KB); restore re-adds them in one transaction and runs `seedMissingYTexts`. Nothing prunes the change log on its own (it travels in backups and exports). Highlight marks and page bodies are intentionally not in the change log.
8. **Subscribe to the store with a selector, never bare `useAppStore()`.** A selectorless call re-renders on every `set()` (each sync event, each debounced save). Use per-field selectors or `useShallow` for multi-field reads.
9. **Password hashing is async and must stay off the event loop.** `hashPassword`/`verifyPassword` (`server/auth.mjs`) use `crypto.pbkdf2` on the libuv threadpool because the process also runs the Yjs relay; a synchronous hash freezes every editor. Login is throttled per username+IP (`server/index.mjs`: 10 failures a minute; the map is capped at 1000 entries, keys clamped to 128 chars, oldest evicted).
13. **A skin must not create stacking contexts on the rails or the content column** (`[data-ui="sidebar"]`, `[data-ui="main"]`: no `backdrop-filter`, `filter`, `transform`, `isolation`, `z-index`). Dialogs opened from the rails now render through `src/components/ui/Portal.tsx` into `<body>` (Chrome painted the History tab's composited scrollers over a fixed overlay left inside a rail, in both themes), but dialogs inside the content column still rely on this rule; a stacking context traps them behind later siblings. The Operations skin uses opaque surfaces and no mount animation. **A skin must never reset `transform` on `*`** (not even under `prefers-reduced-motion`): reset only the transforms the skin itself sets (`src/test/glass-theme.test.ts` guards this). And because unlayered rules beat Tailwind's hover utilities, every surface a skin restyles needs its own `:hover`.
12. **Never copy the live SQLite file or LevelDB directory.** WAL journals and open LevelDB logs make raw copies corrupt. Go through `server/data-export.mjs`, or stop the container.
11. **Never put secrets in `settingsPublic`.** It is mirrored to every connected client; only the public theme and blur-default policies belong there.
10. **Batch CRDT/SQLite writes.** Wrap multi-record Yjs writes in one `sharedTransact` and SQLite batches in one `db.transaction` (`upsertCommandLogBatch`); `PRAGMA synchronous = NORMAL` pairs with WAL so a batch is one commit, not one fsync per row. `db.mjs` also sets `busy_timeout = 5000` and `journal_size_limit` 64 MiB.

14. **No native browser dialogs, one shared Dialog, and native controls follow the theme.** `window.confirm`/`prompt`/`alert` paint outside the skin; use `src/components/ui/ConfirmDialog.tsx` (built on Dialog; optional input, type-to-confirm `match`, `busy`, `error`) or an inline `Banner`. Every modal overlay is `src/components/ui/Dialog.tsx` (portal, `bg-overlay` scrim, aria-labelledby, focus trap and restore, Escape closes only the topmost; a control that wants Escape calls `preventDefault()`); never hand-build a `fixed inset-0` overlay. The scrim stops mousedown/click/contextmenu so a portal's events do not reach the component that opened it. `tokens.css` declares `color-scheme` on `:root`/`.dark` so select popups, date/colour pickers and spinners render dark, and restyles `select` (own chevron, `appearance: none`) and the accent of range/checkbox/date inputs; keep those rules when touching form styling. A page's sections are the run up to its next page-starting break (`sections_by_page`, which holds only when that gives exactly the PDF's page count and, with mixed paper sizes, every section is its page's size); each page's first section gets its own header and footer, and `band_text_gaps` then looks every band page's text up in its own section's header or footer and adds what is not there to the missing lines, so the ladder drops to the rung with the bands in the body. Page numbers are checked the same way: a restart is a `pgNumType` start on the lead section of the page that restarts (`page_number_starts`, never below 0), `band_text_gaps` reads the starts back (`word_page_numbers`) and a page whose printed number the file cannot give is a gap, and a constant after the page field equal to the last printed number becomes NUMPAGES, or a PAGEREF to the `_btct_last_page` bookmark when numbering restarts, but only when what joins them is a separator, one short function word (lower case up to three letters, capitals or title case up to two) or two short lower-case ones (`is_total_connector`: "of", "Of", "out of" count, "Page 3 | Team 3" and "Rev 2" stay text); a footer whose PAGEREF bookmark is gone from the body is a gap too. Without that map a header and footer on different pages stay in the body (`bands-pages-apart`), mixed paper sizes decline only heuristic bands (`bands-mixed-sizes`), and a tagged PDF gets a contents page rebuilt only where its tag tree has a `/TOC` (`toc-untagged`); the rebuild keeps every paragraph between the entries that holds a letter, where it stood, and declines the whole page when one cannot be copied or when a unit it would remove (a table row the entries share) holds a picture or text no entry accounts for (matched whole against the entry texts the stretch's own letters did not hold, never as a substring of the stretch, or a side card reading "Scope" beside an entry "1.1 Scope" was deleted unseen) (`toc-uncovered`, beside `toc-unmatched` and `toc-not-found`; an entry's title or label that ends in a digit is never taken from the front of another entry's that runs on in digits, unless what follows is its own page number (the stretch is glued, so "Phase 1" on page 11 reads "phase111"), or "Figure 1" was taken from "Figure 10", the real label beside the stretch was nobody's, and design-b1's whole contents page was declined; the kept rows of exact height then become at-least). A repair that lifts a running band or rebuilds a table of contents deletes part of the document, and so does any pass that moves a paragraph out of where the converter wrote it; a wrong guess in either is invisible in the result; it **names every run by the family in the staged font file's own name table** (name ID 1 plus the bold and italic bits of name ID 2), because Word matches on that and on nothing else: a run asking for the PostScript name a PDF uses reaches no font, embedded or installed, and Word substitutes in silence, and it **carries only what Word will read**: TrueType outlines, so a PostScript-outline face is redrawn (licence permitting; `--no-font-conversion` stops it), and never a preview-and-print face, which makes Word open the whole document read-only; and it **removes every link whose scheme is not http, https or mailto** before the converter sees the PDF, because Word follows what a hyperlink names and `FILE://host/share` is a credential leak on the reader's machine. Child processes get argv arrays, a minimal env and a timeout; `convert.py` pins numpy's and OpenCV's thread pools to one thread before importing them, because they size themselves to the host's CPUs rather than the container's quota and on a 24-core host the import maps 4.4 GB, which is a SIGSEGV under its own 3 GB `RLIMIT_AS`; error text is path-scrubbed and capped. Do not add a shell string, a path built from CRDT text, or any code that reads asset bytes outside the staging path. One assumption is version-dependent: a staged SVG is never sized, and is safe only because usvg resolves an href for exactly two elements, `<image>` and `<feImage>` (both refused by name, as is any `data:` URI anywhere in the file), and because typst refuses http, file and out-of-root hrefs inside an SVG. Bumping `TYPST_VERSION` in the Dockerfile means re-running those checks ([docs/typst-tab-2026-09.md](typst-tab-2026-09.md)).

19. **Interface zoom is CSS `zoom` on `<html>`** (`src/lib/ui-zoom.ts`, per device in localStorage `btct.uiZoom`, set from Profile or `Mod+Alt+=`/`-`/`0`). Chrome scales viewport units and `position: fixed` offsets by it, and rects and pointer coordinates are screen px while style lengths are CSS px. Size against the viewport with `.h-viewport`/`.w-viewport` or `calc(N * var(--vh))`, never `h-screen`/`w-screen` or raw `vh`/`vw`, and pass any `clientX`, drag delta or rect size through `toLayoutPx` before it becomes a `left`/`top`/`width`. Ratios between two rects are fine as they are.
20. **A relay room answers its first sync only after its stored state has loaded.** y-websocket's own LevelDB binding does not await the load, so a cold room answered sync from an empty doc and the stored body arrived afterwards (duplicated pages, empty exports, half-loaded backups). `server/index.mjs` replaces it through `setPersistence` with one that sets `doc.whenLoaded` (and `doc.loaded`); the `upgrade` handler awaits it before `handleUpgrade`, `data-export.mjs` and `yjs-data.mjs` await it before reading, only when persistence is on (Yjs's own `whenLoaded` on a plain doc never resolves). A room LevelDB cannot read gets a `503` and is dropped from the relay map, never served empty. A connection whose room unloaded in between is closed with `1013` so the client reconnects. A `/yjs/` room name must match `[A-Za-z0-9_-]{1,128}` (else `400`), and every upgrade path that bails after `loadRelayDoc` calls `releaseIdleRoom` so an abandoned upgrade does not pin the doc. Client side, never seed from a timer: `PageEditor.tsx` seeds an empty fragment only once `provider.synced`, and through `seedPageFragment` (`src/lib/page-seed.ts`, a client id derived from the page id and markdown, never `applyTemplate`), so two first openers do not double the body; version restores wait for the same sync (`restorePageVersion`; `whenFullySynced` resolves on a timer and never authorizes a rewrite). `App.tsx` creates the first empty workspace (`seedDefaultWorkspace`, `src/db/seed.ts`; no sample content, and the Report starter is page setup only) only after a real sync of an empty shared doc.
21. **Await every route handler and never let a request exit the process.** Dispatch is `return await handleX(...)` so the router's catch sees the rejection (a bare `return` let one `null` body to `/api/cmdlog/manual` kill Bun). Read request fields only from scalars (`clampStr`/`clampInt`; times through `clampTime`, inside what a `Date` can hold). Never hold a `bun:sqlite` statement across an await: one left mid-`iterate()` stays active and `VACUUM INTO` fails every backup until a restart. A full disk answers `507`. Stream files with `streamFileTo` (`server/assets.mjs`), never `.pipe`: Bun 1.3's node:http does not emit `close` on the response when several clients abort at once, so the helper also destroys the stream when the request closes early. The process-level `unhandledRejection`/`uncaughtException` handlers log and keep serving; they are a backstop, not the error path. A missing static file is a 404; only extensionless paths fall back to `index.html`. `httpServer.headersTimeout` is 30 s (slow-header connections drop); `requestTimeout` is left alone so a large import over a slow link is not cut off.
22. **Relay persistence is `server/relay-persistence.mjs`, never y-websocket's own binding.** It buffers each room and stores one update every 300 ms (sooner past 2 MB or 2000 updates); that update is a merge in groups of 64 (`mergeUpdatesBounded`), or past 1000 buffered updates `Y.encodeStateAsUpdate(doc, sv)`, never one `Y.mergeUpdates` of the whole buffer, which is quadratic in the count and blocked the loop until SIGTERM went unhandled. Never apply a relay message straight from the socket's `message` event either: Bun delivers a socket's buffered messages without returning to the event loop while more data waits, so a fast client starved timers, LevelDB completions and SIGTERM for 40 s on half a CPU; `relay-inbox.mjs` queues them and applies a batch per turn (close applies the rest first, shutdown flushes every inbox before detaching, a deleted account's inbox is discarded). Anything that reads LevelDB directly (backups, exports of closed rooms) first awaits `getPersistence()?.drain?.()` (`drainPersistence()` in `data-export.mjs`). A failed write is kept and retried, never dropped, and turns `/healthz` into a 503 until the LevelDB log has been sealed (`createLevelDbLogSealer`: memtable into a table, new log, old log gone); a write ENOSPC cut short leaves a torn log record and LevelDB's next open drops everything after it, so never report healthy on the first write that succeeds. An update that reaches a room already handed to `writeState` is written at once, and a socket no longer open has its whole inbox applied in one turn. Do not swallow write errors anywhere else.
23. **The server stops on SIGTERM/SIGINT by closing rooms, draining and closing LevelDB, closing SQLite, then exiting 0** (`shutdown()` in `server/index.mjs`). Anything holding state in memory must be flushed from that path. Keep `SHUTDOWN_TIMEOUT_MS` below the container's stop timeout, and never ship compose `init: true` without this handler.
24. **A history twin that cannot be parsed is moved aside (`.ydoc.corrupt-<ts>`), never overwritten,** and twin writes are temp file, fsync, rename, ordered by a sequence number. `flushAllTwins()` stays synchronous: the backup engine copies `*.ydoc` right after it returns.
25. **Health checks test the status line, not the body.** The Dockerfile probe writes `$l`, compose writes `$$l`; both pass only on `' 200 '`. A conditional file in the image is a stage picked by a global ARG, never an `rm` in a later layer. Never track `.env` or key material; `install-btct.sh` and `Start-BTCT.ps1` replace any `AUTH_SECRET` ever committed.
26. **A backup run reads rooms, then the SQLite snapshot, then the assets that snapshot lists, then the twins,** streamed into one `.zip.tmp` that is fsynced and renamed (never held in memory, never a folder). A run complete on disk is a success (and is pruned to keep-last) even when SQLite cannot record its result. A restore never writes into `/data` until everything is staged in `.restore-staging` and read back, and a refused one never writes there at all (no LevelDB or SQLite open to probe a lock; settings read from a temp copy; `--verify` reads a ZIP in place); a ZIP is unpacked only by `zip-stream.mjs` into `.restore-unpack` (unsafe member names refused, each member re-hashed); every manifest id that becomes a path matches `ENTRY_ID_RE` and is listed in `manifest.files`.
27. **A restore that rolls rooms back writes a new `restore_epoch`, and every client honours it.** Every `WebsocketProvider` (export readers included) passes `restoreEpochParams()`, since the relay answers 409 to any other epoch, and nothing opens a Yjs doc before `prepareClientCaches()` resolves in `main.tsx`. Refuse an upgrade only through `refuseUpgrade()` (`server/index.mjs`, answered through `ws`): a raw `socket.write` never leaves under Bun. Browsers cannot read the status, so a failed connect of the shared provider re-checks the epoch at once (`checkRestoreEpochNow`).
28. **Only the client whose transaction changed a collaborative `Y.Text` writes it back to the record, and only that field.** Note images retire late (10 s, removing client only) and un-retire on any insert; the `asset_image` parse rule stays at `priority: 60`, above Crepe's `img[src]`.
29. **Log out only on 401/403; never wait on y-indexeddb's `whenSynced` directly** (use `whenIdbLoaded`). Image byte caches are `ByteLru`-capped (the History tab's version bytes too, 32 MB), `auth-store` writes localStorage only through `safeSet`/`safeRemove` (blocked storage means a memory-only session), `installGlobalErrorLogging` (`src/lib/global-errors.ts`, once from `main.tsx`) only logs `[global-error]`/`[unhandled-rejection]`, every pane renders inside an `ErrorBoundary` keyed on its tab, and client code never calls `crypto.randomUUID` (missing over plain HTTP).
30. **Workspace import and export.** Every download goes through `downloadBlob` (`src/lib/download.ts`, the one download helper; it is also the only caller of the system save dialog, `src/lib/save-dialog.ts`: `showSaveFilePicker` where it exists and the per-device "Ask where to save each export" pref, localStorage `btct.askWhereToSave`, is on, an anchor download otherwise; it resolves `'cancelled'` when the user closed the dialog, which downloads nothing, and asks for one more click through a "ready, Save…" bar when the export outlived the click's activation), and every one but the workspace archive, the notes archive and the report bundle (Export report, `exportReport` in `components/typst/report-bundle-io.ts`, `<workspace>_<YYYY-MM-DD_HHMM>_report.zip` with a root folder; one ZIP like the workspace archive) through `downloadAsZip` (`src/lib/download-zip.ts`: `<name>_<YYYY-MM-DD_HHMM>_<ext>.zip` holding the original file (the extension tag keeps different formats made in the same minute apart), text deflated, compressed formats stored, never a ZIP inside a ZIP); every import of something the app downloads takes the ZIP or the bare file (`readUploadText`, `src/lib/zip-upload.ts`); routes scripts call (`/api/cmdlog/export`) stay raw. Every exported name goes through `export-names.ts`. Import as new mints a fresh id for every record, room and asset and rewrites every reference through one map (delete-entry `pageTree` snapshots included); replace never deletes a record the archive has and merges bodies. Bulk shared-doc writes go in transactions of about 1 MB of JSON (`writeChunked`). Export readers are read-only (`?ro=1`) and name every page they could not confirm; an imported body counts only when the server's state vector covers it. CSV cells starting with `= + - @`, tab or CR get an apostrophe on both client (`csvCell`) and server (`cmdlog.mjs`).
31. **Default accounts are created, never changed.** Every boot, `ensureSeedAccounts` (`server/index.mjs`; pure rules in `server/seed-accounts.mjs`, tested in `src/test/seed-accounts.test.ts`) creates the primary admin (`ADMIN_USERNAME`, default `Roberto`) and the `SEED_USERS` names (default `Warren,Ryan,Anthony,Jesse,Darren`, empty for none) as admins when no account of that name exists in any case. It never resets a password, changes a role, renames, or deletes an old `admin`; the one change to an existing row is promoting the primary on a box with no admin at all. Passwords come from `ADMIN_PASSWORD` / `SEED_PASSWORD_<NAME>` (never logged), else the hardcoded team password `DEFAULT_SEED_PASSWORD` (`typst-best456`), at the owner's request. Usernames are case-insensitive because `users.username` is `COLLATE NOCASE` (since v0.1.0); keep it that way.
33. **Live preview decorations never write to the document.** The syntax markers of the Live preview style (`prefs.editorStyle`, `'live'` | `'blocks'`, default `'live'`) are widget decorations and list item node classes computed from the local selection, its caret slot and Source mode; showing, hiding or moving them dispatches only meta transactions with `addToHistory: false` (stored marks for a slot included) and never a step, so the Yjs fragment, undo, copy and export are identical in both styles and a collaborator in the other style sees nothing of them. Editing commands may change the document: Backspace/Delete next to a revealed marker, `#` before a heading, `*`/`~`/`=` over a selection and `==text==` typed or pasted are ordinary transactions on the real structure (heading level, marks, list/quote lift). Never turn a marker into document text, and switch style or Source mode through `applyEditorStyle` / `setSourceMode`, never an editor rebuild. `src/test/live-preview.test.ts` checks y-prosemirror bindings' state vectors do not move while the cursor, its slot or Source mode does.
32. **A session token never goes in a URL.** `GET /api/backup/archives/<name>` (finished `.zip` runs only, `parseBackupEntryName` validation like the DELETE route, `openBackupArchive` then `streamFileTo`) takes an admin bearer or the backup token in the header; a plain-link download (Firefox, or the pref off) carries a one-time ticket from `POST /api/backup/archives/<name>/ticket` instead (`signTicket`/`redeemTicket` in `server/auth.mjs`: a key derived for the purpose so it never verifies as a session token, 60 s, single use, bound to the archive and an account that must still be an admin). With the save dialog the client fetches with the header and pipes `response.body` into the picked file (`src/lib/backup-download.ts`); never buffer a backup ZIP in page memory.
34. **The report preview's lock and find are one operator's view, never shared state.** The lock is localStorage `btct.typst.previewLock.v1.<userId>` (`src/lib/preview-lock.ts`, `components/typst/use-preview-lock.ts`, every access in a try/catch), per account and per workspace, so two accounts on one browser keep separate locks; never move it into the shared doc, a page doc or server prefs. Locked, `TypstPreview` ignores clicks for navigation and the `.locked .pseudo-link` rule lets a drag on linked text select. Find (`src/lib/preview-find.ts`, `PreviewFindBar.tsx`) searches the text runs of every page fragment (`extractTextRuns`, cached by `data-tid` and checked against the body) only while its bar is open, 150 ms after the query or a recompile settles, and measures highlights only on mounted pages: horizontally from the run's glyph `<use x>` positions matched word for word (`glyphSpan`; typst.ts's `.tsel` selection text is another font stretched to the run, so a Range over it drifts along a line and is only the fallback), vertically from the run's `<foreignObject>`, converted to page units by the card ratio and drawn as `pointer-events: none` boxes in the shadow root. A card with matches drops `content-visibility: auto` (Firefox gives no text rectangles inside skipped content). Its window keydown listener (capture) takes `Mod+F`, `L` and `Esc` only when focus is inside the preview, or the pointer is over it and focus is not in an editable element, so CodeMirror's `Mod+F` (the source find panel) still wins with the caret in the code. Locked, selecting a finding in Findings mode never touches the code editor (no spotlight, scroll, focus, or opening a hidden Code pane); the rail decides this once per selection, so a lock flipped while a finding is open applies to the next selection.
35. **An asset link is resolved where it is pasted, never stored.** `btct-asset:<id>` (`lib/asset-link.ts`) is clipboard text: the Findings form, the report editor and the note editor turn it into a figure slot or an `asset_image` by looking the id up in the workspace's own records, and an unknown id stays as text with a notice, so the report source only ever gains `/assets/<file>` paths and the server export sees nothing new. `asset-link.ts` and `clipboard.ts` are shell imports and must stay free of Typst code (invariant 17). The Findings form never rewrites exploitation markup that `parseExploitSteps` cannot write back unchanged (it returns null and the raw editor stays).
36. **The finding block's arguments are named only in `lib/typst-finding-schema.ts`.** A new argument name hard-coded in the parser, serializer, form, search or copy/paste is a bug; add a `FINDING_SCHEMA` row instead. The form never writes a schema argument the report's `#let finding` does not declare, and never rewrites a block argument the definition does not take. A pasted finding always gets an id free in the target report, and its screenshots arrive as new uploads in the target workspace with crop and blur as metadata, never a reference to another workspace's asset and never baked bytes.

## Performance
Image sizes measured on 2026-10-12 (`docker image inspect`): 996 MB with both build switches on, 907 MB with `WITH_TYPST_CLIENT=0`, 365 MB with `WITH_REPORT_BINS=0`, 276 MB with both off. Change notes for the 2026-10-12 hardening pass, per stream: [docs/competition-fixes-2026-10-12/](competition-fixes-2026-10-12/).

The current implementation and measurements are recorded in [docs/lightweight-redesign-2026-09-06.md](lightweight-redesign-2026-09-06.md).

Generated `dist/` is not versioned. `bun run build` recreates it locally; the Docker client stage always builds from source. Do not commit generated bundles or restore stale recon assets.

The Operations branch uses lazy editor, export, image-editing and account panels. `code-accent.ts` and `editor-keybind-registry.ts` let the shell update preferences without loading editor code. Removing the graph canvas took `@xyflow/react`, `@dagrejs/dagre`, `html-to-image` and `date-fns` out of the client; removing the assistant took `@anthropic-ai/sdk`, `@modelcontextprotocol/sdk` and `zod` out of the server. The three `@myriaddreamin/typst*` packages are back as of 2026-09-19, reachable only through the `lazy()` `typst` tab behind `ENABLE_TYPST`: they put 29.3 MB of WebAssembly plus 8.7 MB of fonts into `dist/` and 55 MB onto the image (with the `.gz` siblings; `WITH_TYPST_CLIENT=0` drops them), and cost a flag-off box 599 gzipped bytes in the entry bundle, 0 requests and no measurable memory. Measurements, commands and all: [docs/typst-tab-2026-09.md](typst-tab-2026-09.md).

Per-page contexts are retained by open page/history tabs and short-lived operation leases. Closing the last tab releases its socket and document after editor cleanup and a committed IndexedDB snapshot. Never delete the persistent cache during teardown. A storage failure keeps the context alive and retries on a later tab change. Exports await the source documents and work in batches of four. `page-context-lifetime.test.ts` covers close/reopen, offline content, leases and failed storage. Selection-only editor transactions reuse decorations through a WeakMap keyed by the immutable document. The UTC clock updates by minute and pauses while hidden; history polling does the same and never overlaps requests. Vite groups icons into one chunk.

Local preview: `docker compose --env-file .env.preview -f docker-compose.preview.yml up -d --build`, bound to `127.0.0.1:8081`, with separate named data and backup volumes, 1 GB memory and two CPUs. That limit is the target machine, not a safety margin: measurements against it live in [docs/lightweight-redesign-2026-09-06.md](lightweight-redesign-2026-09-06.md). `.env.preview` contains generated preview-only credentials and is ignored. Stop with the same compose flags followed by `stop`; this preserves preview data.

Full CPU/memory audit and the fixes applied: [docs/perf-audit-2026-08-19.md](perf-audit-2026-08-19.md); the 2026-08-28 multi-agent pass (54 confirmed findings, what was fixed, what is still open with a recommended fix): [docs/perf-bug-audit-2026-08-28.md](perf-bug-audit-2026-08-28.md). Static assets are precompressed at build time (the Dockerfile gzips `dist/`) and `tryServeStatic` serves the `.gz` sibling plus an mtime+size ETag; only `/assets/*` (hashed names) is `immutable`, everything else is `no-cache`, and `.wasm` must stay in the MIME table (streaming instantiate). Heavy tab views are `lazy()` imports in `SplitContainer`; the interface self-hosts two OFL families in `public/ui-fonts/` (Barlow in latin and latin-ext subsets, about 22 KB and 15 KB per weight, and JetBrains Mono at about 95 KB per style; a browser fetches only the weights a screen uses); the logo ships as `public/favicon.svg`, `favicon.ico`, `apple-touch-icon.png`, `logo-mark-mono.svg` (the sidebar and login `.op-brand-mark` masks it in the primary colour) and `wordmark.svg` (the login `BrandLockup` masks it in the text colour; never set "BTCT" in a font in its place); masters, PNG exports and rules live in `brand/` (`brand/BRAND.md`), never a large PNG in `public/`.
